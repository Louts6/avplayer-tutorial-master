# AVPlayer Tutorial 设计文档

> 项目名称：LearnAV / QtDemo
> 适用版本：C++17 / Qt 6.7.2 / FFmpeg 9.0.1（Windows 桌面）& FFmpeg（Android arm64-v8a / armeabi-v7a）
> 文档目的：作为项目的技术参考资料，系统阐述整体架构、模块职责、数据流、关键技术点、构建系统与跨平台策略。

## 1. 项目概述

### 1.1 项目目标

AVPlayer Tutorial 是一个以 **C++ + Qt6 + FFmpeg** 为技术栈的多媒体教学/演示项目，目标是把一套工业级播放器中常见的核心环节（解封装 → 解码 → 音视频同步 → GPU 滤镜处理 → 渲染显示 → 编码封装）以**模块化、可教学、可跨平台**的方式实现，便于开发者学习与二次开发。

项目对外呈现两层产物：

- **LearnAV**：与平台/框架无关的静态/共享 C++ 库（Windows 上为静态库，Android 上为 JNI 共享库），承担全部多媒体核心逻辑。

- **QtDemo**：基于 Qt Widgets + OpenGL 的桌面端示例 App，验证 LearnAV 的播放、滤镜、录制能力。

- **Android AVPlayerDemo**：基于 Kotlin + GLSurfaceView + JNI 的 Android 端示例 App，验证 LearnAV 在移动端的可移植性。

### 1.2 功能列表

| 功能域  | 能力                                                                       | 关键实现                                                           |
| ---- | ------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 视频播放 | 打开本地视频文件、播放/暂停/Seek/进度回调/EOF 通知                                          | FileReader → AVSynchronizer → VideoPipeline → VideoDisplayView |
| 音频播放 | 同步播放 PCM 音频，可读取播放进度                                                      | AudioDecoder → AVSynchronizer → AudioPipeline → AudioSpeaker   |
| 视频滤镜 | 垂直翻转、灰度、反色、贴纸（人脸检测）                                                      | VideoFilter 子类 + GLSL Shader                                   |
| 视频录制 | 把管线渲染后的视频帧 + 音频样本编码 H.264/AAC 封装成 MP4                                    | FileWriter → AudioEncoder/VideoEncoder/Muxer                   |
| 跨平台  | Windows（Qt6 桌面） + macOS/Linux（Qt6 桌面） + Android（GLES3 + OpenSL ES + JNI） | 平台工厂 + 条件编译                                                    |

### 1.3 技术栈

- **语言**：C++17（核心库）、Kotlin（Android 上层）、GLSL 330 core / GLSL ES 3.0（着色器）

- **GUI/事件循环**：Qt 6.7.2（Core / Gui / Widgets / OpenGL / OpenGLWidgets / Multimedia / Quick）

- **多媒体引擎**：FFmpeg（libavformat / libavcodec / libavutil / libswscale / libswresample）

- **GPU 渲染**：OpenGL 3.3 Core Profile（桌面）、OpenGL ES 3.0（Android）；Windows 下使用 [GLAD](https://glad.dav1d.de/) 加载扩展

- **数学库**：GLM（贴纸滤镜的矩阵运算）

- **图像加载**：stb\_image（贴纸图片加载）

- **人脸检测**：InspireFace（仅 macOS/Linux 启用，用于贴纸滤镜的人脸对齐；Windows/Android 通过 CMake 排除）

- **构建系统**：CMake ≥ 3.22.1；Windows 使用 MinGW 13.1.0 + 预编译 FFmpeg 共享库；macOS/Linux 使用 Conan 2 拉取 FFmpeg/stb/glm；Android 使用 NDK + Gradle + CMake

- **可选缓存加速**：CCache（自动探测）

### 2.2 关键设计原则

1. **接口与实现分离**：每个核心模块都通过 `Interface/I*.h` 提供抽象基类 + 静态工厂 `Create()`，调用方只依赖抽象，便于单元替换和平台分支。
2. **Listener 回调驱动**：模块间通过内嵌 `Listener` 接口做反向回调，避免直接持有下游对象，降低耦合。
3. **生产者-消费者队列 + SyncNotifier**：所有跨线程模块（DeMuxer、Decoder、AVSynchronizer、VideoPipeline、VideoEncoder、AudioEncoder）都使用 `std::list` 队列 + `SyncNotifier`（条件变量封装）做线程间唤醒。
4. **GPU 资源线程亲和**：所有 OpenGL 操作都在专用线程上完成（VideoPipeline / VideoEncoder / TaskPool / 渲染线程），通过共享 `GLContext` 实现纹理跨线程共享。
5. **平台隔离**：通过 `#ifdef ANDROID / _WIN32` + 工厂方法的差异化实现，把平台细节收敛在 `src/Android/` 与 `IAudioSpeaker.cpp` 等少数文件里。

## 3. 模块详细设计

### 3.1 LearnAV/include —— 对外公共接口

| 文件                    | 作用                                                                                                                                                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `IPlayer.h`           | 播放器顶层接口，定义 AttachDisplayView / Open / Play / Pause / SeekTo / AddVideoFilter / StartRecording 等操作；提供静态 `Create(std::shared_ptr<GLContext>)`。                                                                                            |
| `IGLContext.h`        | OpenGL 上下文抽象。在 `#ifdef ANDROID` 分支下使用 EGL + `std::condition_variable` 实现（等待渲染线程通过 `SetSharedEGLContext` 注入共享上下文）；在桌面分支下使用 `QOpenGLContext + QOffscreenSurface`。两者对外 API 一致：`Initialize/Destroy/MakeCurrent/DoneCurrent/WaitUntilReady`。 |
| `IPlaybackListener.h` | 播放事件回调（开始 / 时间变化 / 暂停 / EOF），UI 层实现该接口接收播放状态。                                                                                                                                                                                           |
| `IVideoFilter.h`      | 视频滤镜抽象 + `VideoFilterType` 枚举（kFlipVertical / kGray / kInvert / kSticker）；提供 SetFloat/GetInt/SetString 等通用参数接口。                                                                                                                         |
| `Log.h`               | 跨平台日志宏，Android 走 `__android_log_print`，桌面走 `std::cout/std::cerr`。                                                                                                                                                                       |

### 3.2 LearnAV/src/Define —— 共享数据结构

`Define/` 目录定义贯穿整个管线的数据载体，是模块间解耦的关键。

- **`BaseDef.h`**：定义 `AVFrameFlag` 位枚举（`kKeyFrame / kFlush / kEOS`），用于 Seek 刷新与流结束信号传播。

- **`IAVPacket`**：包装 FFmpeg `AVPacket`，附带 `timeBase`、`flags` 与 `releaseCallback`（弱引用，用于管线资源计数回弹）。

- **`IVideoFrame`**：统一以 **RGBA** 数据流转的视频帧，包含 `width/height/pts/timebase`、`std::shared_ptr<uint8_t> data`、`textureId`（可选 OpenGL 纹理 ID）以及释放回调。析构时若存在 `textureId` 则调用 `glDeleteTextures` 释放。

- **`IAudioSamples`**：统一为 **16-bit 交织 PCM** 的音频样本，含 `channels/sampleRate/pts`、`std::vector<int16_t> pcmData`、`offset`（用于部分写入扬声器时的偏移游标）。

- **`FileWriterParameters`**：录制参数（采样率、声道、宽、高、fps），由 `Player::StartRecording` 在调用 `IFileWriter::StartWriter` 时填充。

> 这种"统一中间格式"策略（视频统一 RGBA、音频统一 S16）简化了上下游模块契约，让 Reader/Writer/Filter 都不必关心原始编解码格式。

### 3.3 LearnAV/src/Interface —— 抽象基类

`Interface/` 是各模块对外契约的统一定义点。每个接口都嵌套一个 `Listener` 内部结构用于反向通知：

| 接口                                             | 职责                                                                                                                                                            | 静态工厂                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `IFileReader`                                  | 文件读取入口：Open/Start/Pause/SeekTo/Stop；GetDuration/GetVideoWidth/GetVideoHeight；通过 `Listener` 上抛音频/视频 Packet 与 Finished 事件                                       | `IFileReader::Create()`                                  |
| `IFileWriter`                                  | 文件写入入口：StartWriter/StopWriter；NotifyAudioSamples/NotifyVideoFrame/NotifyAudioFinished/NotifyVideoFinished                                                     | `IFileWriter::Create(std::shared_ptr<GLContext>)`        |
| `IVideoPipeline`                               | 视频处理管线：AddVideoFilter/RemoveVideoFilter；NotifyVideoFrame/NotifyVideoFinished/Stop                                                                             | `IVideoPipeline::Create(glContext)`                      |
| `IAudioPipeline`                               | 音频处理管线（透传）：NotifyAudioSamples/NotifyAudioFinished                                                                                                             | `IAudioPipeline::Create(channels, sampleRate)`           |
| `IAudioSpeaker`                                | 音频输出：PlayAudioSamples/Stop                                                                                                                                    | `IAudioSpeaker::Create(...)`（平台分发，见 `IAudioSpeaker.cpp`） |
| `IVideoDisplayView`                            | 视频显示视图：SetTaskPool/InitializeGL/SetDisplaySize/Render(frame, mode)/Render(clearColor)/Clear；定义 `EContentMode`（ScaleToFill / ScaleAspectFit / ScaleAspectFill） | `IVideoDisplayView::Create()`（桌面 vs Android 各有实现）        |


### 3.4 LearnAV/src/Reader —— 解封装与解码

#### 3.4.1 FileReader（`Reader/FileReader.cpp`）

`FileReader` 是 Reader 层的编排者，组合 `DeMuxer + AudioDecoder + VideoDecoder`：

```
            ┌──────────────┐
  filePath │  DeMuxer     │  AudioPacket ──┐    VideoPacket ──┐
  ────────►│  (avformat)  ├─────────────────┤──────────────────┤
            └──────┬───────┘                 │                  │
                   │ AudioStream            ▼                  ▼
                   │ VideoStream      ┌──────────────┐  ┌──────────────┐
                   └──────────────────►│ AudioDecoder │  │ VideoDecoder │
                                       │ (swr→S16)    │  │ (sws→RGBA)   │
                                       └──────┬───────┘  └──────┬───────┘
                                              │ IAudioSamples   │ IVideoFrame
                                              ▼                 ▼
                                       (向上抛给 IFileReader::Listener)
```

- 实现 `IDeMuxer::Listener / IAudioDecoder::Listener / IVideoDecoder::Listener` 三个接口。

- 把 DeMuxer 抛上来的 Audio/Video stream 通过 `SetStream` 注入对应 Decoder，建立解码上下文。

- 接收解码后的 `IAudioSamples / IVideoFrame` 并通过 `IFileReader::Listener` 上抛给上层（即 `Player`）。

- `Pause/Stop/SeekTo` 统一调用三个子模块的对应方法。

#### 3.4.2 DeMuxer（`Reader/DeMuxer.cpp`）

- 内部维护独立线程 `m_thread`，循环：`SyncNotifier::Wait(100)` → 检查 seek → 若未暂停且管线资源有配额则 `ReadAndSendPacket`。

- **资源配额（背压）机制**：`StreamInfo::pipelineResourceCount` 初值为 3，每发出一个 Packet 自减；当 `IAVPacket` 析构时其 `releaseCallback` 被触发（弱引用提升），调用 `ReleaseAudioPipelineResource/ReleaseVideoPipelineResource` 把配额加回去并唤醒线程。这是项目核心的流控机制，避免解码器跟不上时 Demuxer 无限堆积 Packet。

- **Seek 流程**：`SeekTo(progress)` 记录目标进度并置 `m_seek=true`，线程在下一轮通过 `av_seek_frame(AVSEEK_FLAG_BACKWARD)` 跳转，随后向 audio/video 各发一个 `kFlush` 标志的空 Packet，触发 Decoder 调用 `avcodec_flush_buffers` 并向下游传播 `kFlush` IVideoFrame/IAudioSamples，最终在 `AVSynchronizer` 中清空队列。

- **EOF 处理**：`av_read_frame` 返回 `AVERROR_EOF` 时把 `m_paused = true`，循环退出（但线程不退出，等待后续 Start）。

#### 3.4.3 AudioDecoder / VideoDecoder

两者结构对称，差异只在编解码与重采样/缩放库：

| 维度           | AudioDecoder                                                                                                                                                          | VideoDecoder                                                                     |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| FFmpeg 上下文   | `AVCodecContext`（用 `avcodec_alloc_context3(nullptr)` + `avcodec_parameters_to_context`）                                                                               | `AVCodecContext`（用 `avcodec_find_decoder` + `avcodec_alloc_context3`）            |
| 转换库          | `SwrContext`，输出 `AV_SAMPLE_FMT_S16`，目标 channels/sampleRate 来自构造参数（默认 2/44100）                                                                                         | `SwsContext`，输出 `AV_PIX_FMT_RGBA`，宽高同源帧                                          |
| FFmpeg 5+ 兼容 | 通过 `#if LIBAVUTIL_VERSION_INT >= AV_VERSION_INT(57, 28, 100)` 选择 `swr_alloc_set_opts2` + `AVChannelLayout` 或老的 `swr_alloc_set_opts` + `av_get_default_channel_layout` | 无（sws API 稳定）                                                                    |
| 输出数据         | `IAudioSamples`（pcmData 为 `std::vector<int16_t>`，含 pts/timebase）                                                                                                      | `IVideoFrame`（data 为 `std::shared_ptr<uint8_t>`，含 width/height/pts/timebase）     |
| 流控           | `m_pipelineResourceCount = 3`，每解码出一帧减 1，帧析构时回调加回                                                                                                                      | 同左                                                                               |
| Flush 处理     | 收到 `kFlush` Packet → `avcodec_flush_buffers` → 向下游发空 `IAudioSamples{flags=kFlush}`                                                                                    | 收到 `kFlush` Packet → `avcodec_flush_buffers` → 向下游发空 `IVideoFrame{flags=kFlush}` |
| 线程模型         | `std::thread` + `SyncNotifier` + `std::list` Packet 队列                                                                                                                | 同左                                                                               |

**关键 API 兼容性写法**（以 `AudioDecoder::SetStream` 为例）：

```cpp
#if LIBAVUTIL_VERSION_INT >= AV_VERSION_INT(57, 28, 100)
    AVChannelLayout out_ch_layout = AV_CHANNEL_LAYOUT_STEREO;
    AVChannelLayout in_ch_layout = m_codecContext->ch_layout;
    if (m_targetChannels == 1) out_ch_layout = AV_CHANNEL_LAYOUT_MONO;
    swr_alloc_set_opts2(&m_swrContext, &out_ch_layout, AV_SAMPLE_FMT_S16,
                        m_targetSampleRate, &in_ch_layout,
                        m_codecContext->sample_fmt, m_codecContext->sample_rate, 0, nullptr);
#else
    m_swrContext = swr_alloc_set_opts(nullptr, av_get_default_channel_layout(m_targetChannels),
                        AV_SAMPLE_FMT_S16, m_targetSampleRate,
                        av_get_default_channel_layout(m_codecContext->channels),
                        m_codecContext->sample_fmt, m_codecContext->sample_rate, 0, nullptr);
#endif
```

通过 `LIBAVUTIL_VERSION_INT` 条件编译同时兼容 FFmpeg 4.x（Conan Linux/Mac）与 FFmpeg 9.x（Windows 预编译库）的 API 差异。`AudioEncoder`、`Muxer` 也采用相同的兼容写法。

### 3.5 LearnAV/src/Engine —— 引擎编排

#### 3.5.1 Player（`Engine/Player.cpp`）

`Player` 是整个库的中枢，同时实现 5 个 Listener 接口把下游模块回调串联起来：

```
IFileReader::Listener        ─► OnFileReaderNotify{AudioSamples|VideoFrame|AudioFinished|VideoFinished}
AVSynchronizer::Listener    ─► OnAVSynchronizerNotify{...}
IAudioPipeline::Listener    ─► OnAudioPipelineNotify{AudioSamples|Finished}
IVideoPipeline::Listener    ─► OnVideoPipelineNotify{VideoFrame|Finished}
```

**串联关系**（构造函数里建立）：

```cpp
m_fileReader    = IFileReader::Create();
m_avSynchronizer = std::make_shared<AVSynchronizer>(m_glContext);
m_audioPipeline  = IAudioPipeline::Create(2, 44100);
m_videoPipeline  = IVideoPipeline::Create(m_glContext);
m_audioSpeaker   = IAudioSpeaker::Create(2, 44100);

m_fileReader   ->SetListener(this);  // FileReader 回调 Player
m_avSynchronizer->SetListener(this); // Sync   回调 Player
m_audioPipeline->SetListener(this);  // Audio  回调 Player
m_videoPipeline->SetListener(this);  // Video  回调 Player
```

**回调链路**：

- FileReader 抛出 `IAudioSamples/IVideoFrame` → Player 转交 `AVSynchronizer`；

- Synchronizer 同步后回吐 → Player 转交对应 `IAudioPipeline/IVideoPipeline`；

- Pipeline 处理完再回调 Player：

  - 音频：Player 把样本喂给 `IAudioSpeaker` 播放、同时若有 `IFileWriter` 喂给录制器，并通过 `IPlaybackListener::NotifyPlaybackTimeChanged` 把当前音频时间戳上报 UI；

  - 视频：Player 把渲染好的 `IVideoFrame` 喂给所有 `IVideoDisplayView::Render`，同时若有 `IFileWriter` 喂给录制器；

  - Finished：音频结束后 `IPlaybackListener::NotifyPlaybackEOF`，并通知录制器音频流结束。

**TaskPool GL 上下文**：`Player::InitTaskPoolGLContext` 在 `m_taskPool` 线程里 `Initialize + MakeCurrent` m\_taskPoolGLContext，供 `IVideoDisplayView::Clear` 等需要在 GL 线程销毁资源的操作使用（`SyncNotifier` 等待完成）。

#### 3.5.2 AVSynchronizer（`Engine/AVSynchronizer.cpp`）

- 以 **音频时钟** 为基准做同步。独立线程循环 `m_notifier.Wait(100) → Synchronize()`。

- `NotifyAudioSamples` 收到样本后入 `m_audioQueue`，处理时直接更新 `m_audioStreamInfo.currentTimeStamp` 并立即下发给下游；`kFlush` 清空两队列，`kEOS` 标记音频流结束。

- `NotifyVideoFrame` 收到帧后入 `m_videoQueue`，处理时比较 `audioTS - videoTS`：

  - `> syncThreshold(50ms)`：视频落后太多，**丢帧**（弹出但不下发，更新 videoTS，continue 下一帧）；

  - `< -syncThreshold`：视频太快，`break` 等待音频追上；

  - 否则：在容忍范围内，下发并 `break`（实现"按音频节奏"逐帧派发）。

- 创建自己的 `GLContext`（共享自 Player 传入的 glContext），原因：同步线程需要持有 GL 上下文以便后续可能的 GPU 操作，同时与渲染线程的纹理共享。

- `Reset()`：置 `m_reset=true`，线程下一轮清空两队列，用于 Seek 后重置状态。

#### 3.5.3 VideoPipeline（`Engine/VideoPipeline.cpp`）

GPU 视频处理线程，是项目最复杂的模块之一：

- **线程入口** **`ThreadLoop`**：启动时 `Initialize` + `MakeCurrent` 共享 GL 上下文（Android 走 `WaitUntilReady` 等待渲染线程注入 EGL，桌面端直接 makeCurrent 一次），创建一个 FBO 作为离屏渲染目标。

- **数据通路**：`NotifyVideoFrame` 把帧入 `m_frameQueue` + `notify_one`；线程取出帧后依次执行：

  1. `PrepareVideoFrame`：准备临时纹理、把 RGBA `data` 上传为 `frame->textureId`，调用内置 `FlipVerticalFilter` 做一次垂直翻转（消除 OpenGL 纹理坐标原点左下与图像原点左上的差异），最后 `std::swap(frame->textureId, m_tempTexture.id)` 让 frame 持有处理后的纹理。
  2. `RenderVideoFilter`：依次调用 `m_videoFilters` 链中每个 filter 的 `Render(frame, m_tempTexture.id)`，每个 filter 把输入纹理渲染到输出纹理（FBO attach 切换 + swap），奇数次渲染后做一次 swap 修正。
  3. `glFramebufferTexture2D(... 0, 0)` 解绑 + `glFinish()` 确保纹理在交给显示线程前完成。
  4. 通过 `Listener::OnVideoPipelineNotifyVideoFrame` 把 frame 回调给 Player。

- **滤镜增删**：`AddVideoFilter` 去重后 push；`RemoveVideoFilter` 把 filter 从主列表搬到 `m_removedVideoFilters`，下一轮 `RenderVideoFilter` 时清理（延迟清理，避免在渲染中途删除正在用的 GL 资源）。

- **平台差异**：

  - **Android**：每帧都要 `WaitUntilReady(10000) → MakeCurrent → EnsureFBO`，因为 context 由渲染线程通过 `SetSharedEGLContext` 异步注入；超时则丢帧（不下发 textureId=0）。

  - **桌面（Qt）**：context 与 shared 同线程绑定，`Initialize` 后只能 `MakeCurrent` 一次，循环内不再重复 makeCurrent，FBO 在循环外创建一次。

#### 3.5.4 AudioPipeline（`Engine/AudioPipeline.cpp`）

非常轻量，仅做透传 + Listener 转发，预留了未来音频处理（增益、混音、效果）的扩展点。

#### 3.5.5 VideoDisplayView（`Engine/VideoDisplayView.cpp`，桌面）

- 实现 `IVideoDisplayView`，使用 `QOpenGLWidget`（实际由 `LearnAV/qt/OpenGLView` 持有）提供的 GL 上下文。

- `InitializeGL`：Windows 下先 `gladLoadGL()`，再编译内置 shader（与 Android 版本源码不同：桌面用 `#version 330 core`，Android 用 `#version 300 es`），创建 VAO/VBO/EBO 画一个四边形。

- `Render(frame, mode)`：仅更新内部 `m_videoFrame` 引用与 mode，不立即绘制（避免跨线程调用 GL）。

- `Render(w, h, r, g, b)`：在 GUI/渲染线程被 `OpenGLView::paintGL` 调用，根据 `EContentMode` 计算 `glViewport` 实现 ScaleToFill/AspectFit/AspectFill 三种填充模式，绘制带纹理的四边形。

- `Clear`：通过 `TaskPool` 把"删除 shader program + 置空 m\_videoFrame"提交到 GL 线程执行，`SyncNotifier::Wait` 等待完成，避免在析构时跨线程访问 GL。

#### 3.5.6 AudioSpeaker（`Engine/AudioSpeaker.cpp`，桌面非 Windows）

- 基于 **Qt6 Multimedia** **`QAudioSink`**，构造时配置 `QAudioFormat`（Int16、目标 channels/sampleRate），打开默认输出设备，启动定时器（50ms）轮询缓冲区。

- `PlayAudioSamples` 入队后立刻尝试 `WritePendingData`；定时器周期性再写一次。

- 缓冲区大小 ≈ 100ms 数据量，`m_audioIODevice->write` 写到 `bytesFree` 上限；通过 `samples->offset` 游标支持一个样本分多次写入。

- Windows 下 `IAudioSpeaker::Create` 返回 `nullptr`（CMake 也把 `Engine/AudioSpeaker.cpp` 排除），故 Windows 桌面端实际无声输出，仅做视频演示；Mac/Linux 完整可用。

#### 3.5.7 GLContext（`Engine/GLContext.cpp` + `Android/AndroidGLContext.cpp`）

跨线程 OpenGL 上下文的核心抽象（详见 §6.3）。

### 3.6 LearnAV/src/Writer —— 编码与封装

`FileWriter` 编排 `VideoEncoder + AudioEncoder + Muxer`，结构与 `FileReader` 对称：

```
IAudioSamples ──► FileWriter::NotifyAudioSamples ─► AudioEncoder ──► IAVPacket ─┐
                                                                                 │
IVideoFrame  ──► FileWriter::NotifyVideoFrame  ──► VideoEncoder ──► IAVPacket ─┤
                                                                                 │
                                                                                 ▼
                                                                              Muxer
                                                                              (avformat + av_interleaved_write_frame)
                                                                                 │
                                                                                 ▼
                                                                              .mp4 文件
```

- **`VideoEncoder`**：H.264 编码器（`AV_CODEC_ID_H264`），目标格式 `AV_PIX_FMT_YUV420P`，time\_base `{1, fps}`，gop\_size=30，max\_b\_frames=1。独立线程 + 共享 GL 上下文，因为输入是 **GPU 纹理**：

  1. `FlipVideoFrame`：调用内置 `FlipVerticalFilter` 把输入纹理翻转回正常方向（解码端在 PrepareVideoFrame 时做过一次垂直翻转，编码前需要还原）。
  2. `ConvertTextureToFrame`：把纹理 attach 到 FBO，`glReadPixels` 读回 RGBA，通过 `sws_scale` 转 YUV420P 写到 `m_avFrame`。
  3. `EncodeVideoFrame`：`avcodec_send_frame + avcodec_receive_packet` 循环，每个 packet 包装为 `IAVPacket` 并设 `timeBase` 回调给 Listener。

- **`AudioEncoder`**：AAC 编码器（`AV_CODEC_ID_AAC`），输出 `AV_SAMPLE_FMT_FLTP`，frame\_size=1024，bit\_rate=128000。`PrepareEncodeAudioSamples` 用 `swr_convert` 把交织 S16 转为 planar FLTP 后送编码。

- **`Muxer`**：用 `avformat_alloc_output_context2("mp4")` 创建输出，分别建 audio/video 流并复制一份 codecpar；`Configure` 内 `avio_open + avformat_write_header`（带 `movflags=faststart`）。收到 packet 后做 `av_rescale_q` 时间基转换，按 PTS 交错写入（`WriteInterleavedPackets` 比较两个队列头部 packet 的秒数，写小的那个）。析构时 `av_write_trailer`。

- **EOS 处理**：`FileWriter::StopWriter` 调用 `NotifyAudioFinished/NotifyVideoFinished`，向两个 encoder 各发一个 `kEOS` 空帧；encoder 收到后调用 `EncodeVideoFrame(nullptr) / EncodeAudioSamples(nullptr)` 刷出剩余 packet 并通知 Finished；Muxer 标记对应流 `isFinished`。

### 3.7 LearnAV/src/VideoFilter —— GPU 滤镜系统

#### 3.7.1 基类 `VideoFilter`

- 实现 `IVideoFilter` 接口，提供 `Render(frame, outputTexture)` 三段式：`PreRender → MainRender → PostRender`。

- `PreRender`：`Initialize`（首次编译链接着色器 + 创建 VAO/VBO 四边形）→ attach outputTexture 到当前 FBO → 检查 `glCheckFramebufferStatus` → `glClear`。

- `MainRender`：绑定输入纹理 `frame->textureId` 到 `GL_TEXTURE0`，设置 `u_texture` uniform，绘制四边形（`GL_TRIANGLE_FAN`，4 顶点）。

- `PostRender`：解绑纹理。

- `Initialize` 懒加载，子类通过 `m_description` 注入着色器源码。

- 通过工厂 `VideoFilter::Create(type)` 按枚举创建子类。

#### 3.7.2 内置滤镜

### 3.8 LearnAV/src/Core —— 通用工具

- **`SyncNotifier`**：基于 `std::mutex + std::condition_variable + std::atomic<bool>` 的事件通知器。`Notify()` 置位并唤醒所有等待者；`Wait(timeout)` 阻塞直到触发或超时，返回后自动 `Reset`。被几乎所有跨线程模块用作"生产者通知消费者"的统一唤醒机制。`Wait(-1)` 表示无限等待。

- **`TaskPool`**：单线程任务队列（`std::queue<std::function<void()>>`），用于把"必须在 GL 线程执行的销毁类操作"从调用方线程转移到 Player 内部的 GL 线程，避免跨线程销毁 GL 资源。

### 3.9 LearnAV/src/Utils —— GL 工具

- **`GLUtils`**：静态方法集 `CompileAndLinkProgram / CheckGLError / GenerateTexture / LoadImageFileToTexture`。

- 头文件包含按平台分发：Android `GLES3/gl3.h`、Windows `glad/glad.h`、其他（Mac/Linux）`QOpenGLFunctions`。

- `GLUtils.cpp` 中 `#define STB_IMAGE_IMPLEMENTATION` 全局唯一实现 stb\_image，给贴纸滤镜加载 PNG。

## 5. 关键技术点

### 5.1 FFmpeg API 兼容性

项目需同时支持 FFmpeg 4.4.4（Conan Linux/Mac）与 FFmpeg 9.0.1（Windows 预编译）。关键差异在 `libavutil` 的声道布局 API：

- **新 API（≥ 57.28.100）**：`AVChannelLayout` 结构体 + `av_channel_layout_default` + `av_channel_layout_copy` + `swr_alloc_set_opts2` + `m_codecContext->ch_layout`。

- **旧 API**：`uint64_t channel_layout` + `av_get_default_channel_layout` + `swr_alloc_set_opts` + `m_codecContext->channels` / `m_codecContext->channel_layout`。

通过 `#if LIBAVUTIL_VERSION_INT >= AV_VERSION_INT(57, 28, 100)` 在 `AudioDecoder.cpp`、`AudioEncoder.cpp`、`Muxer.cpp` 三处分别做兼容分支，保证同一份源码在两套 FFmpeg 上都能编译。

### 5.2 OpenGL 渲染与共享上下文

项目采用 **离屏 FBO 渲染 + 共享纹理** 的多线程 GPU 架构：

1. **主上下文**：桌面端由 `QOpenGLContext::globalShareContext()` 提供（`Main.cpp` 设了 `AA_ShareOpenGLContexts`），Android 端由 `GLSurfaceView` 的 EGL context 提供。
2. **管线上下文**：`VideoPipeline`、`VideoEncoder`、`AVSynchronizer` 各自构造一个 `GLContext`（共享自主上下文），在自己的线程里 `Initialize + MakeCurrent`，所有 GPU 操作都在自己线程完成。
3. **显示上下文**：`QOpenGLWidget` 自带 GL 上下文，与主上下文共享，`paintGL` 里只做"绑定纹理 + 绘制四边形"，不做重计算。
4. **跨线程数据载体**：`IVideoFrame::textureId` 由管线线程创建，被显示线程消费；因为上下文共享，纹理 ID 在两个上下文里都有效。

### 5.3 GLAD 加载（Windows）

Windows 没有内置 OpenGL 1.0+ 的函数指针，必须用扩展加载器。项目选择 **GLAD**：

- `3rdparty/glad/include/glad/glad.h` + `3rdparty/glad/src/glad.c` 由 CMake 通过 `$<${WIN32}:${GLAD_SRC}>` 生成器表达式加入 `LearnAV` 静态库源文件。

- 在 `IVideoDisplayView::InitializeGL`、`MainWindow.h`、`OpenGLView.h`、`GLUtils.h`、`StickerFilter.h` 等头文件中通过 `#ifdef _WIN32` 包含 `glad/glad.h`，并在 `VideoDisplayView::InitializeGL` 中调用 `gladLoadGL()` 完成初始化。

- Mac/Linux 使用 `QOpenGLFunctions` 提供的函数（Qt 已封装），Android 使用 `<GLES3/gl3.h>` 系统头。

### 5.4 线程模型

项目涉及的线程一览：

| 线程                | 归属模块                     | 职责                                         |
| ----------------- | ------------------------ | ------------------------------------------ |
| GUI 主线程           | Qt                       | 事件循环、`QOpenGLWidget::paintGL`、控件信号槽        |
| DeMuxer 线程        | `DeMuxer`                | `av_read_frame` + Packet 分发                |
| AudioDecoder 线程   | `AudioDecoder`           | 解码 + swr 重采样                               |
| VideoDecoder 线程   | `VideoDecoder`           | 解码 + sws 缩放为 RGBA                          |
| AVSynchronizer 线程 | `AVSynchronizer`         | 音视频时钟同步 + 下发                               |
| VideoPipeline 线程  | `VideoPipeline`          | GPU 上传纹理 + 滤镜链渲染                           |
| VideoEncoder 线程   | `VideoEncoder`           | GPU 翻转 + glReadPixels + H.264 编码           |
| AudioEncoder 线程   | `AudioEncoder`           | swr + AAC 编码                               |
| TaskPool 线程       | `TaskPool`（Player 持有）    | GL 资源销毁类任务的串行执行                            |
| Android 渲染线程      | `GLSurfaceView.Renderer` | GLES3 surface 渲染 + 通过 JNI 注入共享 EGL context |
| AudioSpeaker 内部   | `QAudioSink` + `QTimer`  | 桌面音频输出；Android 用 OpenSL ES 回调线程            |

### 5.5 同步机制

- **`SyncNotifier`**：所有"生产→消费"型跨线程通信的统一原语。生产者 `Notify`，消费者 `Wait(timeout)`；`m_triggered` 标志保证即使 Notify 早于 Wait 也不会丢事件。

- **`std::recursive_mutex`**：用于 Listener 指针保护，避免回调链中再次调用同一对象时死锁（如 Player 在 OnAudioPipelineNotifyAudioSamples 中通过 Listener 链调用回 Speaker，路径上需要多次访问 Listener 指针）。

- **资源计数背压**：`DeMuxer::StreamInfo::pipelineResourceCount` 与 Decoder 的 `m_pipelineResourceCount`（初值 3）通过 `IAVPacket/IVideoFrame/IAudioSamples` 析构时的 `releaseCallback`（`std::weak_ptr<std::function<void()>>`）回收配额。弱引用设计避免循环引用：模块持有 `shared_ptr<function>`，数据结构持有 `weak_ptr`，数据析构时 lock 成功则触发回调。

- **AVSync 阈值**：`syncThreshold = 0.05`（50ms），以音频时钟为基准；视频落后 >50ms 直接丢帧，超前 >50ms 等下一帧，否则下发。这是简化的"音频主时钟"策略，适合教学场景。

### 5.6 资源生命周期管理

- 所有跨模块传递的数据用 `std::shared_ptr` 持有（`IAVPacket/IVideoFrame/IAudioSamples`）。

- `IVideoFrame` 析构时若 `textureId != 0` 调用 `glDeleteTextures`——但要求析构发生在持有 GL 上下文的线程；通过 `releaseCallback` 把配额回弹给 Decoder 即可，纹理删除由 GL 自己在合适线程处理（事实上 shared\_ptr 默认在最后一个引用线程析构，可能不在 GL 线程——这是当前实现的已知简化，教学项目可接受）。

- `TaskPool + SyncNotifier` 用于"必须同步等完成的 GL 销毁"：如 `VideoDisplayView::Clear`、`Player::DestroyTaskPoolGLContext`。

## 7. 跨平台策略

### 7.1 平台差异概览

| 维度        | Windows (MinGW)                                             | macOS / Linux                            | Android                                       |
| --------- | ----------------------------------------------------------- | ---------------------------------------- | --------------------------------------------- |
| 构建产物      | 静态库 LearnAV + QtDemo.exe                                    | 静态库 LearnAV + QtDemo                     | 共享库 liblearnav.so                             |
| FFmpeg 来源 | 预编译共享库 (bin/\*.dll)                                         | Conan 包                                  | 预编译 libijkffmpeg.so                           |
| GL 头文件    | glad/glad.h                                                 | QOpenGLFunctions                         | GLES3/gl3.h                                   |
| GL 上下文实现  | `Engine/GLContext.cpp` (QOpenGLContext + QOffscreenSurface) | 同左                                       | `Android/AndroidGLContext.cpp` (EGL)          |
| 显示视图      | `Engine/VideoDisplayView.cpp`                               | 同左                                       | `Android/AndroidDisplayView.cpp`              |
| 音频输出      | 无（返回 nullptr）                                               | `Engine/AudioSpeaker.cpp` (Qt AudioSink) | `Android/AndroidAudioSpeaker.cpp` (OpenSL ES) |
| 上层入口      | `qt/Main.cpp` + Widgets                                     | 同左                                       | Kotlin `AVPlayer.kt` + `PlayerGLSurfaceView`  |
| 滤镜支持      | Flip/Gray/Invert                                            | Flip/Gray/Invert/Sticker                 | Flip/Gray/Invert                              |
| OpenGL 版本 | 3.3 Core                                                    | 3.3 Core                                 | ES 3.0                                        |

### 7.2 平台隔离手段

1. **CMake 排除法**：通过 `list(FILTER ... EXCLUDE REGEX ...)` 把平台不支持的源文件从编译列表移除。
2. **工厂方法分发**：`IAudioSpeaker::Create` / `IVideoDisplayView::Create` 在不同平台编译单元返回不同实现（同一头文件声明、不同 cpp 实现）。
3. **`#ifdef ANDROID / _WIN32`**：在头文件包含、着色器源码、平台特定逻辑（如 EGL 等待）处使用条件编译。
4. **Android JNI 桥接**：`src/Android/JNIPlayer.cpp` 与 `JNIDisplayView.cpp` 提供 C 接口，与 Kotlin `NativePlayer` / `NativeDisplayView` 一一对应。

### 7.3 Android 共享 GL Context 的特殊性

Android 上 GL context 与 EGL surface 绑定到 GLSurfaceView 的渲染线程，**管线线程不能直接 makeCurrent**。解决方式：

1. Kotlin 层 `PlayerGLSurfaceView.Renderer.onSurfaceCreated` 触发 `nativeSetSharedGLContext`，在渲染线程内调用 `eglGetCurrentDisplay/Context`，通过 JNI 传给 `GLContext::SetSharedEGLContext`。
2. `AndroidGLContext` 用传入的 shared context 创建自己的共享 context + 1×1 Pbuffer surface，置 `m_ready=true` 并 `notify_all`。
3. 管线线程（`VideoPipeline::ThreadLoop`）每帧前调用 `WaitUntilReady(10000)` 阻塞等待渲染线程完成注入；超时则丢帧（避免阻塞管线）。
4. 桌面端 `WaitUntilReady` 直接返回 true，因为 Qt 的 `QOpenGLContext::globalShareContext()` 在 `Main.cpp` 启动时就已建立。

### 7.4 平台特定注意事项

- **Windows**：必须用 GLAD 加载 GL 扩展；`glad.c` 由 CMake 注入静态库；`VideoDisplayView::InitializeGL` 中调用 `gladLoadGL()`。

- **Android**：着色器必须以 `#version 300 es` 起头（无前导空白），否则编译失败；项目里 Android 着色器源码用 `R"(...)` 紧凑格式，桌面版用缩进格式。

- **macOS / Linux**：仅在此平台启用 InspireFace + StickerFilter，路径在 `3rdparty/InspireFace-{arch}/lib`（macOS 区分 arm64/x86\_64）。

## 9. 附录

### 9.1 关键模块交互时序（播放首帧）

```
UI: ControllerWidget::onPlayButtonClicked
  └─► Player::Play
        └─► FileReader::Start
              ├─► DeMuxer::Start (notify DeMuxer 线程)
              ├─► AudioDecoder::Start
              └─► VideoDecoder::Start

[DeMuxer 线程]
  av_read_frame → 按 stream_index → OnNotifyAudioPacket / OnNotifyVideoPacket
  → FileReader → AudioDecoder::Decode / VideoDecoder::Decode (入 Packet 队列 + Notify)

[VideoDecoder 线程]
  收到 Notify → DecodeAVPacket → avcodec_send_packet + receive_frame → sws_scale(RGBA)
  → 构造 IVideoFrame (releaseCallback 弱引用到 ReleaseVideoPipelineResource)
  → OnNotifyVideoFrame (FileReader) → OnFileReaderNotifyVideoFrame (Player)
  → AVSynchronizer::NotifyVideoFrame (入 m_videoQueue + Notify)

[AVSynchronizer 线程]
  收到 Notify → Synchronize → 等待音频时钟到达
  → OnAVSynchronizerNotifyVideoFrame (Player) → VideoPipeline::NotifyVideoFrame (入帧队列)

[VideoPipeline 线程]
  收到 Notify → 取出 frame → PrepareVideoFrame (上传纹理 + 垂直翻转)
  → RenderVideoFilter (链式滤镜) → glFinish
  → OnVideoPipelineNotifyVideoFrame (Player)
  → 遍历 m_displayViews → IVideoDisplayView::Render(frame, AspectFit)
        (内部只更新 m_videoFrame 引用)

[GUI 线程]
  OpenGLView::paintGL → IVideoDisplayView::Render(w,h,color) → 绘制 → update() 触发下一帧
```

### 9.2 已知限制

1. **Windows 桌面无音频输出**：`IAudioSpeaker::Create` 在 `_WIN32` 返回 nullptr，CMake 也排除 `AudioSpeaker.cpp`。Windows 用户只能看到视频画面，听不到声音。
2. **`IVideoFrame::textureId`** **销毁线程不保证**：`shared_ptr` 默认在最后一个引用所在线程析构，可能不在持有 GL 上下文的线程。教学项目对此做了简化处理。
3. **InspireFace 仅 macOS/Linux**：Windows/Android 不支持贴纸滤镜，CMake 与 `VideoFilter::Create` 工厂双重排除。
4. **录制不复制时间戳**：`VideoEncoder::EncodeVideoFrame` 用 `++m_avFrame->pts` 简单递增，不严格对齐源时间戳；适合教学，不适合生产。
5. **AudioSpeaker 缓冲策略简单**：50ms 定时器轮询 + 100ms 缓冲，长时间运行可能漂移；Android 用 OpenSL ES 回调更稳定。

### 9.3 二次开发建议

- 若要扩展音频处理（混音/效果），在 `AudioPipeline::NotifyAudioSamples` 里插入处理逻辑即可，下游接口不变。

- 若要新增视频滤镜：继承 `VideoFilter`，构造函数里设置 `m_description.vertexShaderSource/fragmentShaderSource`，在 `VideoFilterType` 加枚举值，在 `VideoFilter::Create` 工厂加 case。多 uniform 可直接用 `SetFloat/SetInt/SetString` + `GetUniformLocation`。

- 若要支持新平台（如 iOS）：参考 Android 分支，新增 `src/iOS/` 平台层 + CMake `if(IOS)` 分支 + 提供 `IVideoDisplayView::Create` / `IAudioSpeaker::Create` 的 iOS 实现。

- 若要严格在生产环境使用：补全 `IVideoFrame` 纹理销毁的线程亲和性（用 `TaskPool` 提交销毁任务）、把 `VideoEncoder` 的 pts 改为基于源 pts 的 `av_rescale_q`、`AudioSpeaker` 改为基于时钟的同步写入。
